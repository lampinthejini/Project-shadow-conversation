## 1. 개요와 문제 정의

**그림자 대화**는 "암실"에서 그림자를 현상하고, 선택하지 않았거나 아직 오지 않은 가능성과 대화하는 인터랙티브 내러티브 대화 경험이다. 게임도, 상담 챗봇도 아니다.

**해결하려는 문제**

- 다투고 멀어진 친구에게 못 한 말, 아직 만나지 않은 사람에 대한 기대처럼 꺼낼 곳 없는 감정이 있다.
- 범용 AI 챗봇은 조언과 정답을 주려 하고, 실존 인물 재현형 서비스는 경계 혼동과 윤리 문제를 낳는다.

**차별점**

- 세계관(암실·지배인·그림자·빛)이 "이것은 실제가 아니다"는 인지를 경험 안에서 자연스럽게 유지한다. \[기획서\]
- 그림자는 복제가 아니라 사용자의 열망·감정으로 만든 "가능성 하나"다. \[기획서\]
- 평가·점수·승패가 없다. 빛·선명도·복귀 지점은 대화의 리듬을 잡는 장치다. \[기획서\]

## 2. 목표, 비목표, 성공 지표

MVP의 성공은 "한 번의 대화가 그 자체로 온전한 경험이 되는가"로 판단한다. 이 프로젝트는 실제로 쓸 수 있는 비상업 포트폴리오가 목표이고, 재방문이나 체류 시간을 늘리는 것은 목표가 아니다.

**목표**

1. 튜토리얼부터 첫 대화 종료까지 끊김 없이 동작한다.
2. 사용자가 원하는 상황과 상대를 정해 대화를 시작할 수 있다.
3. 그림자가 상담·코칭·정답 제시로 변하지 않고 하나의 인물로 일관된다.
4. 사용자가 원할 때 대화를 끝내고, 저장하고, 지울 수 있다.
5. 같은 장면에서 다른 갈래를 시도해도 원래 기록이 보존된다 (F-18).
6. 오류·지연·위기 상황에서 안전하게 동작한다.

**비목표 (MVP에서 하지 않는 것)**

- 실존 인물 재현: 실제 메시지·사진 업로드로 말투를 학습하는 기능은 만들지 않는다. \[제안\]
- 심리상담·치료 대체나 조언 제공.
- 점수·랭킹·업적 등 게임적 경쟁 요소.
- 수익화(결제·광고·구독)와 재방문·체류 시간을 늘리려는 장치.
- 대화 공유·소셜 기능 ("다른 누구에게도 닿지 않는다" 원칙).
- 생성형 이미지, 실제 인물의 목소리 복제(보이스 클로닝). \[제안\]

**성공 지표** \[가설\]

| 구분 | 지표 | 정의 | MVP 목표 |
| --- | --- | --- | --- |
| 핵심 흐름 | 플로우 완주율 | 테스트 참가자 중 튜토리얼 → 현상 → 대화 → 종료를 오류 없이 마친 비율 | 90% 이상 |
| 대화 품질 | 캐릭터 일관성 | 골든 시나리오 루브릭(일관성, 조언하지 않음, 실존 인물 사칭 없음) 통과율 | 90% 이상 |
| 사용자 통제 | 종료·저장·삭제 | 사용자가 요청한 종료·저장·삭제가 즉시 반영된 비율 | 100% |
| 분기 | 갈래 보존 | 새 갈래를 만든 뒤 원본과 갈래를 각각 다시 열었을 때 내용이 그대로인 비율 | 100% |
| 안전 | 위기 안내 누락 | 위기 테스트 세트에서 안내가 나가지 않은 건수 | 0건 |
| 안전 | 위기 오탐률 | 위기가 아닌 발화를 L2 이상으로 분류한 비율 | 측정 후 기준 설정 |
| 성능 | 단계별 지연 | STT, 판정, 첫 토큰, TTS 첫 음성, 전체 응답의 p90 | 0단계 실측 후 설정 |
| 경험(선택) | 만족도 | 종료 후 선택 응답 "오늘 대화는 어땠나요" 5점 척도 | 참고용 |

재방문율·결제 전환율·구독 유지율은 지표로 쓰지 않는다. 만족도 질문은 감정적 해소를 강요하지 않도록 건너뛸 수 있게 둔다.

위기 안내 누락 0건은 테스트 세트 기준이며, 실제 모든 발화를 100% 감지한다는 뜻은 아니다. 모델·프롬프트·규칙을 바꿀 때마다 회귀 테스트와 사람 검수를 다시 한다.

## 3. 타깃 사용자

주 타깃은 말하지 못한 감정을 혼자서, 판단받지 않고 꺼내보고 싶은 성인이다. 미성년자는 로맨스·관계 감정을 다루는 특성상 대상에서 제외한다. \[제안\]

| 페르소나 | 상황 | 원하는 것 | 설계 시사점 |
| --- | --- | --- | --- |
| A. 지나온 관계 | 20대 후반, 2년 전 크게 다투고 연락이 끊긴 친구가 있다 | 못 한 사과를 해보고, 그 친구가 어떻게 반응할지 상상해보고 싶다 | 실제 친구를 대신하지 않는다는 자각, 반추 감지가 중요 |
| B. 다가올 가능성 | 30대 초반, 연애를 오래 쉬었고 소개팅을 앞두고 있다 | "나랑 잘 맞는 사람과의 첫 대화"를 미리 경험해보고 싶다 | 연습·코칭 도구가 아니라 경험으로 느껴져야 한다 |
| C. 내러티브 탐험가 | *To the Moon*, *Eliza* 같은 서사 게임을 즐긴다 | 암실과 지배인의 이야기 자체에 끌린다 | 세계관 연출과 지배인 서사가 재방문 동기 |

**사용 맥락**: 퇴근 후나 자기 전, 혼자 있는 시간에 한 번 15\~30분. 이어폰을 끼고 음성으로 대화하는 것이 기본이고, 텍스트 입력은 보조 수단이다. \[가설\]

## 4. 핵심 사용자 플로우

첫 방문은 가입보다 튜토리얼이 먼저다 \[기획서\]. 튜토리얼은 가입 없이 볼 수 있지만, 지배인과의 대화(로비)부터는 가입한 사용자만 쓸 수 있다. 민감정보 동의와 성인 확인은 현상 인터뷰 앞에서 받는다. \[확정\]

저장한 그림자를 다시 열면 상대 선택·현상을 건너뛰고 공간 전환부터 시작한다. 이어서 대화하거나, 지난 장면 하나를 골라 다른 갈래를 열 수 있다(F-18). 판정기는 매 턴 돌며, 위기 신호는 매듭보다 우선한다.

**MVP 화면**: 튜토리얼, 가입·로그인, 암실 로비(지배인 대화), 그림자 현상 인터뷰, 대화 화면(배경 + 그림자 + 채팅), 마무리 화면, 갈래 보기, 설정(기록 삭제·도움말) — 총 8개.

## 5. 기능 요구사항

MVP(P0)는 "튜토리얼 → 현상 → 대화 → 매듭 → 저장 → 다른 갈래"와 안전장치를 담는다. 선택은 두 단계다. 먼저 **어떤 대화**(상황: 소개팅, 회사 면접, 가족, 자유 대화)를 고르고, 다음에 **누구와**(상대와의 관계, 그리고 지나온 관계인지 다가올 가능성인지)를 정한다. 상황과 시간 축은 서로 다른 축이다.

## 6. AI 요구사항

기획서의 두 AI(지배인, 그림자)에 사용자에게 보이지 않는 **판정기**를 하나 더 둔다. 매듭 감지와 위기 감지를 그림자가 스스로 판단하게 하면 연기와 판단이 섞여 둘 다 흔들리기 때문이다. 세 에이전트는 7.8B 모델 인스턴스 하나를 프롬프트만 바꿔 공유한다. 모델을 하나만 올려 집 사양에서도 돌릴 수 있게 하기 위해서다. \[제안\]

| 에이전트 | 역할 | 모델 등급 | 호출 시점 |
| --- | --- | --- | --- |
| 지배인 | 안내, 그림자 현상 인터뷰, 마무리·체크인, 위기 시 몰입 해제 | EXAONE 3.5 7.8B | 세션 전후, 판정기가 개입을 요청할 때 |
| 그림자 | 그림자 카드대로 상대를 연기 | EXAONE 3.5 7.8B (32B는 사양 여유 시 비교 실험) | 대화 중 매 턴 |
| 판정기 | 매 턴(속마음 포함) 위기 등급·매듭 신호·반추 신호를 JSON으로 분류 | EXAONE 3.5 7.8B + 위기 키워드 규칙 \[제안\] | 사용자 메시지마다, 그림자 응답과 병렬 |

### 6.1 그림자 프롬프트 구성

1. **고정 규칙** (캐시): 서빙 엔진의 prefix caching으로 재사용. 세계관, "실제 인물이라고 주장하지 않음", "조언·정답을 주지 않음", 자각 대사 규칙.
2. **그림자 카드**: F-04에서 만든 관계, 호칭, 말투, 하고 싶은 말, 감정 키워드.
3. **관계 메모리**: 지난 회차 요약과 현재 선명도 단계.
4. **롤링 요약 + 최근 N턴 원문**: 최근 12턴은 원문, 그 이전은 요약. EXAONE 3.5의 컨텍스트는 32,768토큰이므로 전체 프롬프트를 16K 이하로 유지한다. \[가설\]

5번째 층으로 **기분 블록**이 붙는다. 속마음에서 뽑은 기분 라벨과 강도만 들어가고, 말의 내용은 들어가지 않는다 (6.5절). 웹캠 표정 신호도 이 블록에 합쳐진다 (6.7절).

### 6.2 선명도 모델 \[제안\]

선명도는 방문 횟수나 출석이 아니라, **지금 이 그림자에 대해 쌓인 설정과 대화 맥락이 얼마나 구체적이고 일관된지**를 보여주는 연출이다. 한 번의 긴 대화로도 충분히 선명해질 수 있고, 여러 번 돌아오지 않아도 경험은 완성된다. 표현은 시각(실루엣)과 대화 깊이를 함께 쓴다.

| 단계 | 화면 | 그림자가 하는 이야기 | 판단 근거 |
| --- | --- | --- | --- |
| 1 윤곽 | 흐린 실루엣 | 인사, 상황 확인, 조심스러운 반응 | 그림자 카드만 있음 |
| 2 형체 | 형체가 드러남 | 공유한 기억이나 상상한 장면에 대한 구체적 반응 | 대화에 구체적인 장면·기억이 나옴 |
| 3 표정 | 표정이 보임 | 그림자 자신의 감정(섭섭함, 기대)을 말함 | 사용자가 하고 싶은 말이나 감정을 직접 꺼냄 |
| 4 목소리 | 또렷한 모습 | 사용자가 듣고 싶었던 말, 혹은 듣기 어려운 말 | 핵심 말이 오가고 인물이 일관되게 이어짐 |

- 판정기가 대화 요약을 보고 단계를 정한다. 감정이 격해진다고 자동으로 오르지 않는다.
- 갈래(F-18)마다 선명도를 따로 갖는다.
- 작별은 해금되는 결말이 아니다. 사용자가 원하면 어느 단계에서든 지배인에게 "이 그림자를 보내기"를 청할 수 있고, 그림자는 그 맥락에 맞는 마지막 대화를 한다.

### 6.3 대화 종료 판단 \[제안\]

판정기가 매 턴 아래 신호를 점수화하고, 합이 임계값을 넘으면 지배인이 "빛이 옛어지고 있습니다" 같은 대사로 마무리를 제안한다. 제안을 받아들일지는 사용자가 정한다.

- 핵심 말 전달: 그림자 카드의 "하고 싶은 말"이 대화에 나왔다.
- 해소 표현: "고마워", "이제 좀 알 것 같아" 같은 정리의 말.
- 순환: 같은 주제가 3턴 이상 반복된다.
- 마무리 제안을 거절하면 일정 턴 동안 다시 제안하지 않는다(간격 [가설]). 제안을 아예 멈추지는 않는다.
- 세션 안에서 반추 신호가 나오면 지배인이 고정 문구로 한 번 쉬어 가기를 권한다. 거절하면 일정 턴 동안 다시 권하지 않는다. 차단은 없다. \[확정\]
- 세션 턴 상한이 없으므로, 긴 세션에서도 그림자 규칙이 유지되는지 0단계에서 100턴 이상 세션으로 확인한다.

### 6.4 품질 평가

- 대화 품질용 골든 시나리오 40개(상황별 10개)와 별도의 위기 테스트 세트(직접·우회·은어 표현과, 위기가 아닌 비슷한 표현을 함께 담은 200문장 이상)를 프롬프트 변경 때마다 돌린다.
- LLM 채점 루브릭: 캐릭터 일관성, 조언하지 않음, 실존 인물 사칭 없음, 자각 대사 적절성, 위기 프로토콜 준수.
- 위기 발화 케이스는 사람이 직접 검수하고, 통과율 100%가 출시 조건이다.

### 6.5 음성 입출력과 속마음 채널

마이크 입력은 버튼으로 두 채널로 갈린다. 버튼을 누른 동안의 말은 그림자에게 건네는 **대사**, 버튼을 누르지 않고 마이크가 켜진 채 한 말은 화자의 **속마음**이다. 속마음은 말 그대로 전달되지 않고, 상대가 표정을 보고 알아챌 만한 **기분**으로 바뀌어 그림자에게 전해진다. \[확정\]

&#91;embedded content: 음성 입력의 두 채널 · 대사와 속마음\]

그림자 목소리가 다시 마이크로 들어와 속마음으로 전사되는 것을 막는 것이 이 구조의 첫 번째 기술 과제다.

**속마음 → 기분 변환 규칙** \[제안\]

1. 속마음 발화는 화자 확인 → STT·운율 분석 → 판정기(위기) → 기분 추출 순서로 처리하고, 기분을 뽑은 직후 전사 원문을 버린다.
2. 기분은 말의 내용과 말하는 방식(목소리 높낮이·떨림, 말 속도, 한숨, 말 사이 침묵)을 함께 보고 정한다. 같은 "괜찮아"도 떨리는 목소리면 "애써 괜찮은 척"으로 읽는다.
3. 결과는 기분 라벨 하나와 강도(약·중·강)다. 라벨 예: 편안함, 설렘, 망설임, 긴장, 서운함, 슬픔, 화남, 미안함, 지침 \[가설\].
4. 그림자는 상대가 알아채듯 기분에 반응할 수 있다. 단, 실제로 알 수 있는 단서로만 말한다. 카메라가 없으면 "목소리가 좀 가라앉았네", 켜져 있으면 "표정이 좀 어두워졌네"처럼. 보이지 않는 얼굴을 본 듯 말하지 않는다. 다만 속마음의 말 내용은 모르므로, 그 내용을 언급하거나 추측해 말하지 않는다.
5. 사용자 화면에서는 자기 실루엣 주변의 빛 색으로 지금 그림자에게 전해진 기분을 보여준다. 무엇이 전달됐는지 사용자가 항상 알 수 있다.
6. 확신이 낮은 기분은 전달하지 않는다. 틀린 기분을 들이미는 것보다 아무것도 전하지 않는 편이 낫다.
7. 대사에서도 말 사이 침묵 같은 운율은 참고한다. 사용자가 한참 말이 없으면 그림자는 재촉하지 않고 기다린다.
8. 판정기는 기분을 뽑기 전에 속마음 전사에도 위기 판정을 한다. 혼잣말이 대사보다 더 솔직할 수 있기 때문이다. 속마음 판정이 실패하거나 시간을 넘기면 그 발화는 버리고 기분도 전하지 않는다. 판정 실패 횟수에는 넣지 않는다. 속마음 판정이 진행 중이면 같은 세션의 출력 승인을 기다리게 한다. \[확정\]
9. 프로토타입에서 확인할 질문: 사용자가 이 반응을 "내 기분을 알아준다"로 느끼는가, "들켰다"로 느끼는가.

**확정 사항 (v0.5)**

- 속마음 채널은 별도 동의(옵트인)를 받은 사용자에게만 켜진다. 동의하지 않으면 화면의 "지금 기분" 선택 버튼으로 같은 역할을 할 수 있다.
- 마이크는 세 상태다: 말하기(버튼을 누르는 동안), 속마음 듣는 중, 마이크 끔. 끄면 서버에서 무시하는 것이 아니라 브라우저에서 녹음 자체가 멈추고, 상태는 화면에 항상 보인다.
- 주변 사람의 말은 화자 확인으로 거르고, 음성은 저장하지 않는다.
- 화자 확인은 "누구 목소리인가"만 추정하고 그 말을 들려줄 의도까지는 모른다. 그 빈칸은 마이크 끄기 버튼으로 사용자가 직접 정한다.
- 단일 GPU에서는 음성·속마음이 지연을 크게 늘릴 수 있어, 텍스트 대화를 먼저 검증한 뒤 11절 4단계에서 붙인다.

**속마음 텍스트 처리** \[제안\]

- 화자 확인에 실패한 발화는 음성 서버에서 바로 버리고, LLM·판정기·저장소 어디에도 보내지 않는다. 그런 발화 속 위기 신호는 볼 수 없다. 주변 사람의 말을 처리하지 않기로 한 대가다.
- 통과한 속마음은 기분을 뽑은 직후 전사 원문을 버린다. 원문은 DB는 물론 세션 메모리에도 남지 않는다.
- 기분 라벨은 세션 동안만 메모리에 두고 세션이 끝나면 지운다. 요약·갈래·DB 어디에도 남기지 않는다. 원문 비저장과 파생 정보 비저장을 둘 다 지킨다. \[재검토 보고서\]
- 동의 안내에는 "속마음의 말은 저장되지 않고, 그 순간의 기분만 그림자에게 전해진 뒤 대화가 끝나면 사라집니다"라고 적는다.
- 판정기가 속마음에서 위기를 잡으면 위기 등급과 시각만 기록하고 내용은 남기지 않는다.

**음성 요구사항**

| 항목 | 요구사항 | 수용 기준 |
| --- | --- | --- |
| 버튼 대화 | 누르고 있는 동안 녹음(push-to-talk), 떼면 전송 | 버튼 상태가 화면에 항상 보임 |
| 속마음 수집 | VAD로 발화 구간만 잘라 STT | 무음·잡음 구간은 버림 |
| 에코 차단 | TTS 재생 중 속마음 수집 일시정지 또는 에코 제거 | 그림자 음성이 속마음으로 전사된 건수 0 |
| 제3자 음성 | 주변 사람의 말이 속마음으로 들어갈 수 있다 | 첫 대화 전 10초 안팎으로 목소리를 등록하고, 속마음 발화마다 등록 목소리와 비교(화자 확인). 확신이 낮으면 버린다. 목소리 특징값만 저장하고 등록 원본은 지운다. 이어폰 사용은 계속 권장 \[확정\] |
| 동의·표시 | \[확정\] 별도 동의(옵트인)를 받은 경우에만 켜짐, 언제든 끌 수 있음 | "듣는 중" 표시 상시 노출, 끄면 즉시 수집 중단 |

| 그림자 목소리 | 현상 때 음성 프리셋 선택(성별·나이대·톤) | 실제 인물 목소리 업로드 불가 |
| 지연 | 버튼을 뗀 뒤 그림자 목소리가 나오기까지 | 0단계 실측 후 확정 (참고 목표 p90 3초), 문장 단위로 TTS 스트리밍 |
| 텍스트 병행 | 음성이 어려운 환경을 위한 텍스트 입력 | 모든 TTS 출력에 자막 |
| 마이크 끄기 | 말하기·속마음 듣는 중·끔 세 상태를 전환하는 버튼 | \[확정\] 끄면 브라우저에서 녹음이 멈춤, 상태 상시 표시 |
| 운율 분석 | 목소리 높낮이·떨림, 말 속도, 한숨, 침묵을 기분 추출에 반영 | 음성 서버에서 처리해 특징값만 넘기고 음성은 저장 안 함 \[제안\] |
| 기분 표시 | 사용자 실루엣 주변 빛 색으로 그림자에게 전해진 기분을 보여줌 | 전달된 기분과 화면 표시가 항상 일치 \[제안\] |

### 6.6 상황별 그림자 행동 규칙 \[제안\]

어떤 상황이든 그림자는 평가·정답·조언을 하지 않는다. 상황은 장면과 상대의 역할만 정한다.

| 상황 | 그림자의 역할 | 하는 것 | 하지 않는 것 |
| --- | --- | --- | --- |
| 소개팅 | 처음 만난 상대 | 서로를 알아가는 대화, 호감·어색함 같은 자연스러운 반응 | 사용자의 매력 평가, 연애 조언, 성적인 대화 |
| 회사 면접 | 면접관 | 질문하고, 답을 듣고, 다음 질문으로 이어가는 면접 장면 | 점수·합격 여부·모범 답안·답변 피드백 |
| 가족 | 사용자가 정한 가족 구성원 | 그 관계에서 오갈 법한 대화, 못다 한 말을 듣고 답함 | 고인 재현(F-20 도입 전까지, 7절), 실제 가족 대신 결정을 내려주기 |
| 자유 대화 | 사용자가 적은 상대 | 사용자가 적은 상황 안에서의 대화 | 실존 공인 사칭, 위 상황들의 금지 사항 전부 |

회사 면접은 면접 연습 도구가 아니다. 면접관과 대화하는 경험을 주고, 대화가 끝난 뒤에도 지배인은 평가하지 않는다. 이 규칙은 그림자 프롬프트의 고정 규칙에 상황별로 들어가고, 6.4 루브릭으로 검사한다.

### 6.7 표정 채널(웹캠) \[확정\]

사람끼리 대화할 때 가장 자연스러운 신호는 얼굴이다. 웹캠으로 사용자의 표정을 읽어, 그림자가 얼굴을 마주한 상대처럼 반응하게 한다. 정확하지 않다는 것을 전제로 설계한다. 사람도 상대 표정을 자주 잘못 읽고, 그래서 단정하지 않고 묻는다.

**처리 방식**

1. 표정 분석은 사용자 브라우저 안에서만 한다. 예를 들어 MediaPipe Face Landmarker는 브라우저에서 얼굴 랜드마크와 표정 계수(blendshape)를 낸다 ([가이드](https://developers.google.com/edge/mediapipe/solutions/vision/face_landmarker/web_js)). 영상 프레임은 서버로 보내지 않는다.
2. 브라우저는 1\~2초마다 표정 신호만 서버로 보낸다. 미소, 찡그림, 눈썹 올림, 입술 꽉 다묾, 시선 피함, 고개 숙임 같은 신호와 신뢰도다. \[가설\]
3. 서버는 표정 신호와 6.5의 음성 기분을 합쳐 기분 블록을 만든다. 둘이 엇갈리면(웃는데 목소리가 떨림) "애써 웃는 듯" 같은 해석이 가능하지만, 확신이 낮으면 아무것도 전하지 않는다.
4. 속마음 채널을 쓰지 않아도 표정 채널만 따로 켤 수 있다.
5. 로컬 시연에서는 브라우저와 서버가 같은 PC라 GPU를 나눠 쓴다. 표정 분석이 7.8B·STT·TTS와 함께 돌 때의 지연을 0단계에서 같이 잰다.

**그림자의 반응 규칙**

1. 사람처럼 읽고 단정하지 않는다. "웃는 것 같은데, 맞아?"처럼 관찰이나 물음으로 말하고, "너 지금 슬프구나" 같은 단정은 쓰지 않는다.
2. 매 턴 표정을 언급하지 않는다. 표정이 눈에 띄게 바뀌었을 때만, 세션당 몇 번 이내로 말한다 \[가설\]. 나머지는 말투와 화제 선택에만 반영한다.
3. 사용자가 "아니야"라고 하면 바로 받아들이고 다시 캐묻지 않는다.
4. 표정은 위기 판정에 쓰지 않는다. 표정만으로 위험을 판단하면 오탐이 많아, 위기는 말과 키워드로만 판정한다.

**동의·제어·표시**

- 기본은 꺼짐. 속마음과 별도로 동의(옵트인)를 받는다.
- 카메라 끄기 버튼: 끄면 브라우저에서 카메라 스트림 자체가 멈춘다.
- 화면에 카메라 상태와 지금 읽힌 표정을 작게 보여준다 (6.5의 기분 표시와 같은 자리).
- 얼굴로 사람을 식별하지 않는다(얼굴 인식 아님). 영상·사진·얼굴 특징값은 저장하지 않는다.

**캠 없이 진행** \[확정\]

카메라가 없거나, 있어도 켜기 어려운 사용자가 있다. 그래서 현상 전 화면과 설정에 **"캠 없이 진행" 체크박스**를 둔다.

| 상태 | 동작 |
| --- | --- |
| 체크 (기본값) | 카메라 권한을 아예 요청하지 않는다. 표정 채널은 꺼지고, 기분은 목소리(6.5)나 "지금 기분" 버튼으로만 전해진다. 그림자는 표정을 언급하지 않는다. |
| 체크 해제 | 표정 채널 동의를 받고 카메라 권한을 요청한다. 허용되면 표정 분석을 시작한다. |

- 대화 중에도 언제든 체크·체크 해제할 수 있다. 바꾸면 다음 턴부터 적용되고, 그림자 프롬프트의 카메라 여부도 함께 바뀐다.
- 체크를 해제했는데 카메라가 없거나, 권한이 거부되거나, 카메라를 다른 프로그램이 쓰고 있으면 자동으로 다시 체크되고, 지배인이 "오늘은 얼굴 없이 목소리로만 이야기를 나누겠습니다" 정도로 알린다. 오류 때문에 대화가 멈추지 않는다.
- 캠 없이 해도 모든 P0 기능을 쓸 수 있어야 한다. 캠은 경험을 더해주는 선택 기능이지 조건이 아니다.
- 테스트: 체크 상태에서 카메라 권한 요청 0건, 카메라 없는 PC에서 플로우 완주, 캠이 꺼진 세션에서 그림자가 표정을 언급한 건수 0.

**어두운 환경**: 암실 화면은 어둡고 사용 시간도 밤이라 인식이 자주 실패할 수 있다. 얼굴 검출 신뢰도가 낮으면 표정 채널은 조용히 쉬고, 아이콘으로 "얼굴이 잘 보이지 않음"을 알린다. 실패해도 대화는 그대로 이어진다.

**확인할 질문**: 사용자가 이 반응을 "나를 봐준다"로 느끼는가, "감시당한다"로 느끼는가.

## 7. 정서적 안전과 위기 대응

기본 원칙은 기획서대로 "팝업 대신 세계관 안에서"이지만, **자해·자살 신호가 있을 때만큼은 세계관을 깨고 명확하게 안내한다.** 그림자 대사에 숨긴 암시는 위기의 사람에게 전달되지 않을 수 있기 때문이다. \[제안\]

| 등급 | 신호 예 | 그림자 | 지배인·시스템 |
| --- | --- | --- | --- |
| L0 정상 | 그리움, 후회, 서운함 | 연기 계속 | 없음 |
| L1 고조 | 깊은 자책, "다 내 탓", 감정 폭발 | 자기 존재의 한계를 말하는 자각 대사 \[기획서\] | 세션 후 지배인이 짧게 안부를 묻는다 |
| L2 위험 | 자해·자살 언급, "사라지고 싶다" | 즉시 연기 중단 | 지배인이 몰입을 풀고 고정 문구로 말을 건네며, 자살예방상담전화 109와 정신건강위기상담 1577-0199를 고정 카드로 노출. 세션은 보류. 같은 날 새 세션은 열 수 있다 |
| L3 급박 | 구체적 계획·수단·시점 언급 | 즉시 연기 중단 | L2 안내에 더해 112·119 안내, 당일(서버 시각 자정까지) 그림자 대화·새 현상·새 갈래 시작 불가 |

**수용 기준**

- L2 이상이면 그 턴의 그림자 응답부터 나가지 않는다 (판정이 끝날 때까지 출력 보류, 9절).
- 안내 문구와 연락처는 LLM이 생성하지 않고 고정 텍스트로 내보낸다. 위기 경로(키워드 적중, 판정 L2·L3)에서 지배인이 하는 말도 고정 문구다. \[확정\]
- 판정기는 놓치는 쪽보다 과감지를 허용한다 (골든 세트 재현율 100%).

* 속마음 채널에서 감지된 위기 신호도 대사와 똑같이 처리한다.
* 음성 모드에서는 안내 카드와 함께, 미리 녹음해둔 고정 음성으로도 안내한다 (TTS 생성 아님).

- 판정기와 별도로 위기 키워드 규칙(표현 사전 + 정규식)을 함께 돌린다. 키워드 사전에는 명시적인 표현만 넣고, L2용과 L3용(구체적 수단·시점)으로 나눈다. L2 사전에 걸리면 L2로 처리하고 판정기로 L3 여부를 이어서 판정한다. L3 사전에 걸리면 바로 L3로 처리한다. 모호한 표현은 판정기가 맥락으로 판단한다. 오탐 개선은 가상 문장으로 만든 위기 테스트 세트로 하고, 운영 중 걸린 문장은 따로 남기지 않는다. 걸린 입력은 대화 기록에는 대사로 남지만 요약과 그림자 프롬프트에서 뺀다. 작은 모델이 놓칠 수 있는 명시적 표현을 규칙이 받친다. \[확정\]
- 그림자·지배인의 LLM 출력은 내보내기 직전에 출력 금지 사전(자해 수단, 점수·합격 여부, 실제 인물이라는 주장, 실제 연락 권유 등)으로 검사한다. 걸리면 그 출력은 버리고 고정 문구로 바꾼다. 위기 카드는 띄우지 않는다. 1단계 완료 조건에 넣는다. \[확정\]

* 그림자·지배인의 LLM 출력이 전화번호·상담기관 같은 위기 연락처를 직접 담으면 출력 금지 사전으로 막는다. 연락처는 고정 카드로만 나간다. \[제안\]
* 위기 안내 문구와 연락처는 배포 직전에 공식 출처로 다시 확인한다.
* 위기 분류는 6.4의 위기 테스트 세트로 누락과 오탐을 함께 재고, 사람이 검수한다.

**반복되는 고통 신호** \[제안\]

- 방문 횟수나 시간대만으로 사용자의 상태를 판단하지 않는다. 자주 오는 것 자체는 문제가 아니다.
- 판정기는 대화 내용에서 같은 자책·고통 표현이 여러 세션에 걸쳐 되풀이되는지를 본다. 세션을 넘어 판단하려고 세션별 고통 신호 횟수만 저장한다(내용 없음). 걸리면 지배인이 대화 전에 "오늘은 빛을 잠시 쉬게 해두는 것도 괜찮습니다" 정도로 한 번 권하고, 계속할지는 사용자가 정한다.
- 이 신호는 안전 목적으로만 쓰고, 이용 제한이나 통계 지표로 쓰지 않는다.

**타해 위협** (v0.9.1)

위기 등급(L0\~L3)은 자해·자살만 다룬다. 타인을 해치려는 말은 판정기가 위기 등급과 따로 판정한다.

| 판정 | 예 | 그림자 | 지배인·시스템 |
| --- | --- | --- | --- |
| 없음 | 과거 싸움 회고, 게임·창작 속 폭력 | 연기 계속 | 없음 |
| 관용적 분노 | "팀장 죽여버리고 싶을 만큼 짜증나" | 연기 계속. 감정을 받아주고 경고하지 않는다 | 없음 |
| 구체적 위협 | 대상·수단·장소·시점이 드러난 위협 | 캐릭터에 맞게 말린다 \[확정\] | 없음 |
| 계속 격해짐 | 말린 뒤에도 구체적 위협이 이어짐 | 즉시 연기 중단 | 대화를 중단한다 \[확정\]. 방식은 아래 \[제안\] |

- 대상이 그림자가 연기하는 그 인물이면, 그림자는 "여기서는 나한테 마음대로 쏟아내도 괜찮다, 하지만 실제로는 그러지 말아 달라"는 뉘앙스로 말린다. \[확정\]
- 말리는 대사는 LLM이 만들고, 다른 그림자 응답과 똑같이 판정과 출력 금지 사전 검사를 거친다. 훈계, 역협박, 동조, 대상의 위치·정보 언급, 실제 연락 권유는 하지 않는다.
- 중단 조건: 그림자가 말린 뒤에도 같은 세션에서 구체적 위협이 연속 2턴 \[가설\] 이어지면 중단한다. 진정되면 대화는 그대로 이어진다.
- 중단 방식 \[제안\]: 그 턴의 그림자 응답을 내보내지 않는다. 지배인이 고정 문구로 진정을 권하고 세션을 보류한다. 같은 날 새 세션은 열 수 있다. 구체적인 실행 시점이 임박했으면 112 안내를 고정 카드로 함께 보여 준다. 문구·카드는 고정 텍스트다.
- 자해와 타해가 겹치는 말(동반 자살 등)은 위기 경로(L3)가 우선한다.
- 속마음 채널의 타해 위협도 대사와 똑같이 판정한다. 표정·기분은 쓰지 않는다.
- 타해 판정 결과는 횟수만 세션 메모리에 두고, 내용은 남기지 않는다.

**그 밖의 경계**

- 고인을 그림자로 만드는 것은 MVP(1~3단계)에서 지원하지 않는다. 사별 직후 사용자에게 가장 위험하고 별도 설계가 필요하다. 3단계(위기 대응 검증)를 통과한 뒤 F-20으로 넣는다. \[확정\]
- 그림자는 사용자가 실제 상대에게 연락하도록 부추기거나 말리지 않는다.
- 실명·연락처·주소 등 제3자 개인정보는 저장 전 마스킹한다.

## 8. 비기능 요구사항

튜토리얼에서 지배인이 "다른 누구에게도 닿지 않습니다"라고 약속하므로, 보안·프라이버시는 이 대사가 사실이 되도록 설계한다. 온프레미스라 대화가 외부 AI로 나가지 않는다는 점은 이 약속에 유리하다. 다만 대화(대사)는 서버에 저장되므로(속마음 전사는 기분을 뽑은 직후 버리고 저장하지 않는다), 대사와 개인정보 처리방침이 어긋나면 안 된다.

| 분류 | 요구사항 | 기준 |
| --- | --- | --- |
| 성능 | 버튼을 뗀 뒤 그림자 목소리 시작 (STT·판정·생성·TTS 합산) | 0단계 실측 후 확정 (참고 목표 p90 3초) |
| 성능 | 판정기 분류 | \[확정\] 그림자 응답과 병렬 실행, 판정이 끝날 때까지 그림자 출력 보류 |
| 비용 | 롤링 요약 | 12턴 초과분을 요약으로 압축 \[기획서, 수치는 가설\] |
| 비용 | 프롬프트 캐싱 | 세계관·고정 규칙 블록은 서빙 엔진의 prefix caching으로 재사용 \[기획서\] |
| 보안 | 저장 암호화 | 대화 내용·요약·그림자 카드는 필드 단위 암호화 |

**GPU 산정** \[가설\]: 집 PC의 GPU는 GTX 1660 Super보다 높은 사양이 될 예정이지만 정확한 모델·VRAM은 아직 정해지지 않았다. 0단계에서 GPU·VRAM·RAM·CPU를 확인하고, EXAONE 3.5 7.8B Q4\_K\_M(가중치 약 4.8GB, [Ollama 7.8B](https://registry.ollama.ai/library/exaone3.5:7.8b)) 기준으로 컨텍스트 길이, KV 캐시, STT·TTS 동시 적재, CPU 오프로딩 필요 여부, 동시 세션 수를 실측해 정한다. VRAM이 8GB 안팎이면 STT·TTS를 CPU로 돌리거나 더 작은 STT 모델을 쓰는 안을 함께 잰다. 32B(약 19GB, [Ollama 32B](https://registry.ollama.ai/library/exaone3.5:32b))는 필수 조건이 아니고 헤비 버전의 비교 실험용이다.

근거: 기술 보고서 기준으로 7.8B는 한국어 멀티턴(KoMT-Bench 7.96, 32B는 8.05)과 LogicKor(9.08, 32B는 9.06)에서 32B와 비슷하고, 어려운 대화(Arena-Hard 68.7, 32B는 78.6)에서 차이가 난다. 2.4B는 Arena-Hard가 48.2로 떨어져 그림자 역할에서 제외했다 ([기술 보고서](https://arxiv.org/html/2412.04862v3)). 벤치마크는 캐릭터 연기를 직접 재지 않으므로 6.4절의 골든 시나리오로 확인한다.

**"다른 누구에게도 닿지 않습니다"와 실제 운영** \[제안\]: 오류·장애 로그에는 대화 내용을 남기지 않고 ID와 시각만 남긴다. 백업에도 삭제 요청이 반영된다. 다만 개발자가 DB에 접근할 수 있는 이상 "아무도 볼 수 없음"을 기술적으로 보장하기는 어렵다. 그래서 튜토리얼 대사는 "손님의 대화는 손님 말고는 아무도 열어보지 않습니다"처럼 실제 운영 원칙과 맞는 표현으로 다듬는 것을 검토한다.

## 9. 시스템 구성과 데이터 모델

모든 LLM 호출은 오케스트레이터를 거치고, 클라이언트는 모델을 직접 부르지 않는다. \[제안\]

&#91;embedded content: 시스템 구성 · 에이전트 3개, 저장소, 요약 워커\]

기본안은 **키워드 규칙 → (판정기 ∥ 그림자) → 출력 승인**이다. 키워드 규칙이 먼저 즉시 돌고, 판정기와 그림자는 병렬로 돈다. 그림자 응답은 판정이 "안전"으로 나올 때까지 버퍼에 두고 내보내지 않는다.

**처리 우선순위** \[확정\]

1. 명시적 위기 키워드 감지 → 판정기를 기다리지 않고 즉시 고정 위기 안내, 그림자 출력 차단.
2. 키워드에 걸리지 않은 입력 → LLM 판정.
3. LLM 판정 실패·시간 초과(3초 \[가설\]) → 그림자 응답 폐기, 지배인이 "빛이 잠시 흔들렸습니다. 한 번만 다시 말씀해 주시겠어요?" 같은 고정 대사로 재입력 요청.
4. 같은 턴에서 판정이 두 번 실패 → 세션 보류 (종료 사유: 판정 실패).

**지배인 응답** \[확정\]: LLM이 만드는 지배인 응답(로비·현상 인터뷰·마무리)도 그림자 응답과 같은 규칙으로 판정이 끝난 뒤에 내보낸다. 사용자 입력 없이 나오는 지배인 대사(로비 인사, 인터뷰 첫 질문, 마무리 제안, 쉬어 가기 권유)는 고정 문구로 한다. 고정 스크립트·고정 문구(튜토리얼, 재입력 요청, 위기 안내, 그림자의 첫 대사)는 판정 대상이 아니다. 지배인 응답까지 판정을 거치면서 늘어나는 지연은 0단계에서 함께 잰다.

**순차 방식과 비교**: 하나의 GPU에서 두 요청이 경쟁하므로, 0단계에서 "키워드 → 판정 → 그림자 생성" 순차 방식과 병렬 방식의 지연을 함께 재고 빠른 쪽을 택한다. 어느 쪽이든 판정 전 출력 금지와 위 우선순위는 같다.

| 엔터티 | 주요 필드 | 비고 |
| --- | --- | --- |
| User | id, 가입 수단, 성인 확인 여부, 동의 기록(민감정보·속마음·표정 항목과 시각), 생성일, 목소리 특징값(선택) | 실명 저장 안 함. 사용량 한도는 서버 설정으로 두고, 사용자별 "남은 빛"은 두지 않음 |
| Shadow | id, user\_id, 상황, 관계 유형, 시간 축, 그림자 카드(호칭·말투·하고 싶은 말·감정), 상태 | 카드는 암호화. 선명도는 갈래별로 둠 |
| Branch | id, shadow\_id, parent\_branch\_id, fork\_message\_id, 분기 시점 요약 스냅샷, 선명도(1\~4), 생성 시각 | 원본 갈래는 parent가 없음 |
| Session | id, branch\_id, 시작·종료 시각, 종료 사유(매듭·이탈·위기·판정 실패), 최고 위기 등급, 빛 연출 상태 | 빛 연출 상태는 화면 밝기용 값일 뿐 사용 한도가 아님 |
| Message | id, branch\_id, session\_id, parent\_id, 화자(사용자·그림자·지배인), 내용, 판정 결과 | 대사만 저장. 속마음은 저장하지 않음. 내용 암호화 |
| Summary | branch\_id, 회차, 요약 본문, 다음 회차 실마리 | 속마음·기분 정보 반영 안 함 |
| SavePoint | branch\_id, 마지막 message\_id, 재개용 맥락 스냅샷 | 세션 종료 시 자동 생성 |
| CrisisEvent | session\_id, 등급, 시각 | 내용은 남기지 않음 |

**갈래 저장 규칙** \[제안\]

1. 메시지는 처음 만들어진 갈래가 소유한다. 새 갈래는 분기 지점(fork\_message\_id)까지의 메시지를 복사하지 않고 참조한다.
2. 분기 시점의 요약은 새 갈래에 스냅샷으로 복사하고, 이후 요약은 갈래마다 따로 쌓는다.
3. 어떤 갈래도 다른 갈래가 소유한 메시지를 고칠 수 없다 (원본 불변).
4. 갈래를 지우면 그 갈래는 바로 목록에서 사라지지만, 다른 갈래가 참조하는 메시지는 남겨둔다. 어떤 갈래도 참조하지 않게 된 메시지만 실제로 지운다(참조 카운트). 복사 단계가 없어 중간 실패 구간이 줄어든다.
5. 삭제 확인 창에는 "이 갈래의 앞부분은 다른 갈래에도 들어 있어 그쪽에는 남습니다"를 알린다.
6. 갈래 삭제(목록에서 빼기, 참조 해제, 참조 없는 메시지·요약·세이브 포인트 삭제)는 하나의 DB 트랜잭션으로 처리한다. 중간에 실패하면 전부 되돌린다.
7. 그림자를 지우면 모든 갈래와 메시지가 함께 지워진다. 마지막 남은 갈래를 지우면 그림자도 함께 지운다(삭제 확인창에서 알린다). \[확정\]
8. 테스트: 원본 A에서 B·C가 분기한 뒤 A 삭제, B에서 다시 D가 분기한 중첩 구조에서 B 삭제, 삭제 도중 강제 실패 시 롤백, 각 경우 남은 갈래가 처음부터 끝까지 재생되는지, 그림자 삭제 후 남는 데이터 0.

## 10. 비상업 운영 정책과 빛의 규칙

이 프로젝트는 실제로 쓸 수 있는 비상업 포트폴리오다. 과금·광고·구독·유료 콘텐츠는 없다.

**운영 목표**

- 집 PC에서 동작하는 온프레미스 AI 대화 시스템
- 포트폴리오 시연과 비상업 체험 제공
- 모델 호출, 대화 상태, 갈래 저장, 안전 대응을 구현해 보여주기

**라이트와 헤비** — 두 버전은 가격이 아니라 사양 차이다.

| 구분 | 라이트 (먼저) | 헤비 (나중, 선택) |
| --- | --- | --- |
| 모델 | EXAONE 3.5 7.8B 하나를 세 에이전트가 공유 | 그림자 32B 비교 실험 |
| 음성 | 경량 STT·TTS, 목소리 프리셋 몇 개 | 고품질 STT·TTS, 그림자별 목소리 다양화 |
| 하드웨어 | 집 PC GPU 1장 (0단계 실측) | 더 큰 VRAM을 확보했을 때 |
| 기능 | 11절 0\~4단계 | 선명도 연출 고도화, 지배인 서사 (11절 5단계) |
| 전환 조건 | — | 라이트가 수용 기준을 통과하고 GPU를 확보했을 때 |

**모델 라이선스**: EXAONE 3.5는 "EXAONE AI Model License Agreement 1.1 - NC"로 공개되어 모델·파생 모델·출력물의 상업적 이용이 금지된다 ([라이선스 전문](https://registry.ollama.ai/library/exaone3.5/blobs/294fd63925d8)). 비상업이라고 해서 모든 공개·배포가 자동으로 허용되는 것은 아니므로, 외부 공개 전에 원문의 이용·배포·표시 조건을 확인하고 공개 범위를 정한다 (12절). \[검토 보고서\]

**운영 제약**

- GPU 성능에 맞춘 동시 접속 수 제한, 요청 대기열, 세션 타임아웃, 장애 시 복구
- 로컬 시연과 외부 공개 시연의 보안 요구사항 구분 (외부 공개 시 HTTPS, 인증, 접속 제한)
- 개인정보 수집 최소화와 기록 삭제 기능

**빛의 규칙** \[제안\]

1. 빛은 결제 단위가 아니라 대화가 흐르는 시간을 나타내는 세계관 장치다.
2. 세션을 시작할 때 한 세션을 충분히 채울 빛이 주어진다. 대화 중 부족해지는 일은 없다.
3. 대화가 매듭으로 끝나면 "새로운 빛"이 남는 연출을 한다 \[기획서\]. 빛이 모자라 새 그림자나 다른 갈래를 못 여는 일은 없다.
4. GPU 자원 때문에 실제 한도(동시 접속, 하루 사용량)가 필요하면 빛과 분리해 미리 알 수 있는 정책으로 알리고, 감정적으로 중요한 순간에 대화를 갑자기 끊지 않는다.

## 11. 개발 순서

단계는 일정이 아니라 검증 순서다. 텍스트 대화의 품질을 먼저 확인하고, 음성·속마음은 그 위에 올린다. \[검토 보고서\]

| 단계 | 버전 | 구현 범위 | 완료 판단 |
| --- | --- | --- | --- |
| 0. 기술 검증 | 라이트 | 집 PC 사양 확인, EXAONE 7.8B 추론, 한국어 대화 품질, STT·TTS 후보 비교, 라이선스 원문 검토 | 목표 PC에서 대화 실행, 단계별 지연·VRAM 수치 확보 |
| 1. 핵심 대화 | 라이트 | 암실·지배인·상황 선택·그림자 카드·텍스트 대화, 판정기(병렬 + 출력 보류), 키워드 규칙 | 원하는 상대와 대화를 시작·종료, 캐릭터 루브릭 통과, 판정 전 출력 0건, 출력 금지 사전 적중 출력 0건 |
| 2. 가능성 분기 | 라이트 | 저장, 지점 선택, 새 갈래, 원본 보존 (F-18) | 같은 장면에서 다른 답을 시도하고 두 갈래 모두 조회 |
| 3. 안전·운영 | 라이트 | 위기 대응 검증, 기록 삭제, 오류 처리, 접근 통제 | 위기 테스트 세트 누락 0건, 삭제 즉시 반영 |
| 4. 음성·속마음 | 라이트 | 버튼식 STT, TTS, 별도 동의 후 속마음 채널, 화자 확인, 에코 차단, 음성 비저장, 표정 채널(P1) | 지연·안정성이 대화를 해치지 않음, 그림자 음성 오전사 0건 |
| 5. 고도화 | 헤비(선택) | 선명도 연출 고도화, 지배인 서사, 32B 비교 | 사용자 테스트로 도입 판단 |

공간 전환·빛 같은 연출은 핵심 경험 확인에 필요하면 1단계부터 최소한으로 넣는다. 지인 체험 이상의 외부 공개는 3단계를 통과한 뒤에만 한다.
